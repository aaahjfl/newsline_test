# 🧩 跨语言召回方案对比（毕设可选）

## 方案一：统一多语 Embedding（推荐主线方案）

### 💡 核心思想

不做翻译，将不同语言的文本映射到同一语义向量空间，直接做相似度检索。

### 🔄 Pipeline

topic（任意语言） → multilingual embedding → 向量检索（全语言标题库） →
top-k 候选标题 → 图链接聚类（事件发现） → 时间抽取（spaCy） → SLM
时序推理 → 时间线输出

### ✅ 优点

-   无需翻译，避免误差传播
-   天然支持跨语言召回
-   与 SBERT 聚类逻辑一致
-   工程简单

### ❌ 缺点

-   依赖多语 embedding 模型质量
-   对极短 topic 仍有不确定性

------------------------------------------------------------------------

## 方案二：多语言 Query Expansion（翻译增强版）

### 💡 核心思想

将 topic 扩展成多语言 query，再分别检索并合并结果。

### 🔄 Pipeline

topic（中文） → 翻译 / LLM 扩展（多语言） → 多 query 检索 → merge 去重 →
图链接聚类 → 时间抽取（spaCy） → SLM 时序推理 → 时间线输出

### ✅ 优点

-   对短文本更稳
-   可控性强
-   对 embedding 依赖较小

### ❌ 缺点

-   依赖翻译或 LLM 质量
-   工程复杂
-   可能引入噪声

------------------------------------------------------------------------

## ⚖️ 对比总结

  维度           多语 Embedding   Query Expansion
  -------------- ---------------- -----------------
  是否需要翻译   ❌               ✅
  工程复杂度     低               高
  稳定性         高               中
  短文本适应     中               高

------------------------------------------------------------------------

## 🎯 建议

优先采用多语 Embedding，可结合 Query Expansion 做增强。
